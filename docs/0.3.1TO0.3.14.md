# Product Evolution: v0.3.1 -> v0.3.14

This document introduces the major changes shipped between `v0.3.1` and `v0.3.14`.
It focuses on the product direction of the `0.3.2` to `0.3.14` release line: simplifying the session workspace, rebuilding review around a PR-style diff experience, and making long agent conversations easier to write, follow, and inspect.

## Snapshot

Between `v0.3.1` and `v0.3.14`, iKanban changed in four visible ways:

- the experimental session task graph was removed so the product could focus on its strongest session workflows,
- change review became a fuller project-level experience with reliable historical and apply-patch diffs,
- conversation history gained clearer tool identity, timing, spacing, and MCP result rendering,
- the overall cockpit became denser, more responsive, and more accessible across desktop and mobile.

The release line also improved tab-scoped server selection, server-backed session archives, prompt composition, browser titles, documentation, licensing, and project navigation.

## Product direction

### At `v0.3.1`

The previous release line introduced a session ikanban task graph for inspecting parent and child agent work. It made multi-agent structure more visible, but it also added a separate graph and detail workflow beside the core conversation and review surfaces.

### By `v0.3.14`

iKanban is more focused on the day-to-day supervision loop:

- open the home board and select active work,
- follow agent activity in a readable conversation timeline,
- identify tool calls and inspect their results,
- review current or historical file changes,
- write and expand prompts without losing conversation context.

The main evolution in this range is not a new top-level surface. It is the consolidation and refinement of the surfaces users rely on throughout a session.

## 1. The session task graph was removed

`v0.3.2` and `v0.3.3` removed the session ikanban task graph, its node detail views, and the related state and helper code.

This reversed the graph experiment introduced in `v0.3.0` and simplified the project structure. Instead of maintaining a separate visualization mode, the following releases concentrated on the home board, conversation timeline, prompt composer, tool output, and change review.

The result is a narrower product scope with less dead code and fewer competing interaction models inside a session.

## 2. Review became a PR-style project workflow

`v0.3.5` delivered the largest review change in this release range.

- the diff panel was redesigned around a familiar PR-style layout,
- project changes are fetched with one full-context VCS diff call instead of separate per-file reads,
- modified files no longer lose their diff when individual file content cannot provide enough context,
- the review header summarizes file counts and added and removed lines,
- file filtering makes larger change sets easier to navigate,
- viewed-file progress is persisted across the review workflow.

Later releases extended that foundation:

- `v0.3.10` restored historical session changes in the sidebar,
- `v0.3.11` reconstructed historical session diffs and apply-patch file changes so they render reliably in review and tool output.

Together, these changes make review useful both while an agent is working and after a session has finished. Users can inspect the current project state, revisit earlier work, and understand patches without leaving the session context.

## 3. Conversations became easier to scan

The conversation timeline received continuous refinement from `v0.3.4` through `v0.3.14`.

- `v0.3.4` added per-tool call durations and total session run time.
- `v0.3.10` introduced distinct tool badges so different operations are recognizable at a glance.
- `v0.3.11` compacted tool-call history and timing details to reduce visual noise.
- `v0.3.12` refined spacing between turns, thinking rows, context tools, and assistant text.
- `v0.3.13` improved MCP tool result details and spacing.
- `v0.3.14` preserved a comfortable desktop conversation width in fullscreen mode.

These improvements are especially important for long-running agent sessions. Timing communicates where work is being spent, badges expose the shape of the workflow, and clearer spacing separates reasoning, tools, results, and final responses without making the history unnecessarily tall.

## 4. Prompting became more flexible

`v0.3.9` added an expandable prompt composer with localized controls, responsive behavior, and accessibility coverage.

The expanded composer gives longer instructions more room while keeping the normal compact mode available for short prompts. The session todo dock also defaults to collapsed from `v0.3.5`, leaving more space around the primary writing surface when a session opens.

Together, these changes make the composer better suited to both quick follow-ups and detailed task descriptions.

## 5. The cockpit was polished across desktop and mobile

`v0.3.7` and `v0.3.8` applied broad visual and interaction refinements across the application.

- session and prompt layouts became denser and more consistent,
- settings, dialogs, navigation, and error states received stronger responsive behavior,
- mobile viewport handling and session spacing were improved,
- accessibility behavior was strengthened across key controls,
- home board interactions became clearer,
- project directory selection was simplified to one workspace at a time.

The ikanban panel also defaults to closed from `v0.3.4`, reducing initial clutter when entering a session. By `v0.3.14`, fullscreen mode keeps the normal readable conversation measure rather than stretching content across the entire display.

The cumulative result is a workspace that uses screen space more deliberately without sacrificing readability.

## 6. Session and server state became more predictable

Two changes in `v0.3.6` improved behavior across browser tabs and devices:

- the active OpenCode server is preserved independently per browser tab, so changing one tab no longer redirects another tab to the same server,
- archived sessions are persisted through the OpenCode SDK instead of browser-only storage, making archive state part of the server-backed session model.

Browser tabs also became easier to identify in `v0.3.3`, when the active server name was added to the page title and static title handling was removed in favor of route metadata.

These changes make multi-server and multi-tab workflows safer because each tab communicates and preserves its own context more clearly.

## 7. Navigation, identity, and documentation matured

The surrounding product experience also became more complete:

- `v0.3.4` replaced remaining OpenCode branding in the interface with the iKanban icon,
- `v0.3.4` added Chinese and English README variants with remote-control agent guidance,
- `v0.3.6` refreshed the README diff panel preview,
- `v0.3.8` added the MIT license and aligned package and README license details,
- `v0.3.13` enabled keyboard scrolling throughout the full session conversation,
- `v0.3.14` linked the home icon to the iKanban GitHub repository.

These are smaller than the review and conversation changes, but they make the project easier to recognize, navigate, evaluate, and use.

## 8. Project tooling stayed current

The release line included two contributor-facing updates:

- `v0.3.4` updated `@opencode-ai/sdk` to `1.17.18` for current upstream fixes and compatibility,
- `v0.3.7` added the `design-taste-frontend` skill to support more deliberate frontend design and redesign work.

These changes kept the OpenCode integration current while documenting a stronger design standard for future interface work.

## What changed in practice

For users upgrading from `v0.3.1`, the practical difference is straightforward:

- sessions place less emphasis on a separate task graph and more emphasis on conversation and review,
- project diffs are more complete and easier to review at a glance,
- historical and apply-patch changes remain visible and understandable,
- long tool-heavy conversations are denser but clearer,
- longer prompts are easier to compose,
- desktop, fullscreen, and mobile layouts behave more consistently,
- server and archive state better match multi-tab and server-backed workflows.
