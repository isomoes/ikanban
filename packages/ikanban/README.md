# `@isomoes/dsh-ikanban`

Keyboard-oriented iKanban web application bundle for DeepSeek Harness.

The host runtime delegates to the published DSH prerelease (`0.1.0-rc.6`). The
web shell is locally owned through the private sibling `ui-layout`,
`ui-sidebar`, and `ui-workspace` sources. The main package combines them into
one browser module, so a DSH profile installs only `@isomoes/dsh-ikanban`.

## Structure

```text
src/
  index.ts       bundle plugin entry
  startup.ts     startup companion entry
  invariant.ts   invariant companion entry
cordis.patch.yml bundle composition patch
scripts/
  sync-upstream.mjs  refresh the stock composition from dsh-web-app
tests/
  upstream-parity.test.mjs  guard delegated entries and patch parity
```

## Local Development

Prerequisites are Node.js 22.19+ or 24+, pnpm 11.7.0, and the published DSH
CLI. Confirm that this repository and the CLI use the intended versions:

```bash
node --version
pnpm --version
dsh --version
```

Install dependencies. The primary development command then builds iKanban,
links its checkout into a dedicated profile, and starts that profile. It is
safe to run from a clean DSH home because it creates or refreshes the profile
before every launch:

```bash
pnpm install
pnpm dev
```

The DSH plugin command used internally adds only this bundle to the profile and
records it as a `link:` dependency.

To inspect the composition without booting, install or refresh the profile and
then dump it. The output must contain an
`@isomoes/dsh-ikanban` bundle layer, with the `web-startup` and `web-runtime`
rows resolving to this package:

```bash
pnpm dev:install
pnpm dev:config
```

The stock server prints its URL and uses `http://127.0.0.1:3080` by default.
Pass Web application arguments after the script separator when needed:

```bash
pnpm dev -- --port 8080
```

### Edit Cycle

The profile links this checkout, but DSH runs built `lib/` files. After changing
`src/`, rebuild and restart the running process:

```bash
pnpm build
# Stop the existing pnpm dev process, then:
pnpm dev
```

`cordis.patch.yml` is generated by `pnpm build` from the installed
`@deepseek-ai/dsh-web-app` patch. It replaces the startup and runtime package
names plus the layout, sidebar, and workspace rows. Change
`scripts/sync-upstream.mjs` rather than editing the generated patch directly.

Each private UI workspace tracks its browser module in `src/client.js`. The
main build combines all three into this package's `lib/client.js` artifact.
`pnpm dev` watches those sources, rebuilds the aggregate artifact, and reloads
the browser page through DSH's rebuild event stream. The full-page reload is
intentional because the three shell plugins share one published client module.
For a production build, run `pnpm build` after editing any of them.

### Checks

Run the local checks before packing or publishing:

```bash
pnpm test
pnpm typecheck
pnpm --filter @isomoes/dsh-ikanban pack
```

Remove the development profile dependency when it is no longer needed:

```bash
pnpm dev:remove
```

`pnpm install` permits `koffi`'s native install script because the stock DSH
composition includes its native directory picker.

The vendored browser sources are the readable rc.6 build output because the
published packages do not include their original TSX. Future layout work should
be made directly in the corresponding local package and covered by its tests.
